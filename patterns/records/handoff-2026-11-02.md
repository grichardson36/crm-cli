## How the owner works with agents

- Communication rules are in `CLAUDE.md`: concise, plain language, the most important point last, reference codes for three or more items, no flattery, no analogies, no decorative headings. Deliver only what was asked. Do not claim completion without evidence. Never add a co-author to a commit message (this overrides any harness reminder that asks for one).
- The owner wants decisions raised as numbered questions with a recommendation, then waits for answers. Key changes are never made without telling the owner first (bare keys act on objects, ctrl keys move the view).
- Work happens in git worktrees: `git -C crm-cli worktree add .claude/worktrees/<name> -b <branch> main`, one agent per branch, branches fast-forwarded into `main` and pushed. Agents run in the background and report back. If an agent stops on a rate limit, resume it with a message instead of doing its work yourself.
- Verify before merging: `go build ./...`, `go vet ./...`, `go test -count=1 ./...`. `-race` cannot run on this machine (no C compiler). `TestListingFiveThousandContactsIsFast` and `TestFind_Performance` are timing tests that fail when several test runs share the machine, rerun them alone. Merge `main` into the branch first, resolve conflicts keeping both intents, run the tests, then fast-forward `main` from the main checkout.
- Test migrations on a copy of the real database in a temp folder, never on the real one, and never run tests against it. After merging, build to `deploy/dist/crm-vNN.exe`, rename the running `bin/crm.exe` to `crm.exe.prev` (Windows allows renaming a running executable) and copy the new one in. The owner then reopens the program.
- The `!` prefix runs commands in Git Bash: use `cp` and forward slashes.
