# Open discrepancies

Remove an item when it is fixed. Add one when a representation is neither the source of truth, a derived projection nor a boundary translation, or when a concept has competing names. State the conflict, governing note, owner question and initial recommendation. Surface it to the owner ([[core]]). %%Denotes direct comments from user%%

- X12. Open and Mark are one verb with one key now (`enter` and `e` are the action `activate`, `x` is `mark-state`, `m` is `merge`, [[core]]), but the handlers behind them are still written per view (Home row, linked row, org and deal edit, task edit, inbox accept) and found by a short list in `internal/tui/verbs.go` (`activateTargets`, `mergeTargets`). Reduced in feat/keymap-a. Breaks [[standards/interface]] and [[core]] only on the handler side. Question: should each object register its own activate handler in the object registry? Recommendation: yes, when the next object is added, not before.
- X17. The command bar and `crm do` cannot attach a note or task to an organization or deal. The only sigil is `@` for a person ([[core]]). Notes reach organizations and deals through `log add --org|--deal`, MCP `org_ids`, and `a n` then `tab` on the org or deal page. Breaks [[core]] for the bar.
- X23. The device-to-device sync contract is decided ([[standards/integration]]) but not built. The DAV phone mapping is still open: DAV ORG has a decided rule ([[core]]), but other flat fields (address, phone, email, title vs role) have no accepted mapping, and the round trip rewrites the phone's text. Proposed rules are in [[research-sync-standard]].
- X41. `people.company` is still a core person field and public input, then creates or updates the same Person–Organization link. It is a second source of the organization fact. Breaks [[core]] and [[standards/product-model]]. Owner direction: the primary Person–Organization link is the source; CSV and vCard company values are boundary translations. Recommendation: migrate non-ignored values to links, then remove the field and its public inputs ([[features/product-model]] R01 and R06).
- X42. The same record is named `interaction` in storage and MCP, `note` in the interface, and `log` in verbs. It has competing product names. Breaks [[core]]. Owner direction: **Activity** is the public object name, with a type such as note, call, email or meeting. Recommendation: rename every door together ([[features/product-model]] R02).
- X43. Task creation and update accept both singular `PersonID`/`DealID` and plural `PersonIDs`/`DealIDs`; the repository appends the singular values to the plural lists before creating activity-target links. The singular inputs are redundant aliases. Breaks [[core]]. Owner direction: use plural target inputs. Recommendation: remove the singular inputs after every door uses the plural form.
- X44. Organization automation copies `people.title` into the role of a newly created Person–Organization link. Title and link role are separate facts, so this creates a second value without an explicit user choice. Breaks [[core]]. Owner direction: keep the facts independent. Recommendation: remove the automatic copy and leave role blank unless supplied for that link.
- X45. Relationship records use mixed storage names: `*_link`, `*_relation`, bare pairs and `activity_target`; `org` abbreviates Organization in names and IDs. The former link map also incorrectly claimed separate `task_*` and `interaction_*` storage keys when both use `activity_target`. Breaks core gate 4 and [[standards/product-model]]. Owner direction: use full singular `<source>_<target>_link` keys: `person_organization_link`, `person_person_link`, `organization_organization_link`, `deal_person_link`, `deal_organization_link` and `activity_target_link`. Use `OrganizationIDs` for collections and `PrimaryOrganizationID` for a deal's derived primary-organization projection. Tags remain attachments, not links. Recommendation: correct the model map, then rename tables, columns, model and API fields together in one migration.
- X48. The Tags right pane shows only the roll-up count of tagged objects. Breaks [[core]] (gate 4, an object list already exists elsewhere) and the universal verbs. Owner direction (2026-11-02): the pane lists the objects carrying the tag, and the usual verbs act on them: `enter` opens the object, `d` removes it from the tag (untags), `space` and bulk verbs apply. Recommendation: reuse the grouped list and the notes-feed row component.
- X49. Four legacy feature IDs name different records: `A16` (enrichment and anniversary), `A18` (organization/deals and middle name), `E11` (pre-meeting brief and Activity date editing), and `M23` (Settings polish and fields/editors). This breaks the stable-ID rule. Question: which record, if any, retains each bare ID? Recommendation: choose one canonical ID for each collision, then give the other record a new ID with an explicit migration entry. Until then, worklists use qualified temporary labels.
