## What changed in this branch (owner items 2 and 3)

- `t` is Add task in every module again, Birthdays included. Go to today is `ctrl+t` (also `ctrl+up`), registry action `go-today`. Its anchor per module: Birthdays today's divider (past above), Tasks the first task dated today or later (else the top), Home, People and Follow-up the top of the list. Organizations, Deals, Merge, Archived, Sync and Company review have no anchor and leave the key alone. The footer shows `ctrl+t today` in Birthdays, the palette shows it everywhere.
- ctrl+t before: no use in code. Two tests used it as an example rebind (`crm keys set tier ctrl+t`, `view-tasks` rebound to `ctrl+t`); both moved to `ctrl+e`. No user config can have depended on it.
- Global "add any object" is `ctrl+a`, action `add-any` (title "New: add any object"). Owner rejected `ctrl+n`, which stays down/next in lists, overlays and the command line. ctrl+a had no use in the registry. It is tmux's default prefix key (`ctrl+b` is tmux's, `ctrl+a` is GNU screen's and a common tmux rebind) and readline's line start, so it stays rebindable. Inside a prompt or a text field it is still line start, the chord only fires in normal mode and in the bar.
- ctrl+a opens a picker of kinds built from the objects registry (Person, Organization, Deal, Task, any registered kind added later) plus Note (which asks for a person first), then runs that kind's normal add flow in a borrowed empty view of that kind. When the flow ends the view, cursor and selection you came from come back, and the bar too when it was open. One undo step comes from the add flow. Read-only mode blocks it. `a` and `+` stay the in-view add.

## Bare keys that move the view or the interface (against the owner rule)

The owner rule is that bare keys act on objects and ctrl keys act on the interface and the view ([[ctrl-moves-the-view-bare-moves-the-object]]). Today these bare keys do not follow it.

| Key | Does | Kind | Recommendation |
|---|---|---|---|
| `1` to `9`, `0` | go to the Nth module | view navigation | keep (module tabs show the number) or move behind the `g` prefix like Gmail and Linear (`g` then letter). Owner decision. |
| `[` `]` | previous and next module | view navigation | keep, they pair like vim and lazygit tab keys |
| `v` | list of modules | view navigation | keep, or fold into the palette |
| `g` `G` and home end | top and bottom | motion | keep, vim motion (general) |
| `J` `K` | scroll the detail pane | motion | keep |
| `h` `l` `tab` `shift+tab` `left` `right` | move the pane focus | motion | keep |
| `o` | sort (People) | view setting | rename to a ctrl form or a palette-only action |
| `r` | reload | interface | keep, or `ctrl+r` |
| `m` | cycle duplicate level (Merge) | view setting | palette only, or a letter that is free |

## A3. Registry rules checked against how [keys] works today

| Idea | Today | Finding |
|---|---|---|
| Load-time conflict check | `keys.Load` normalizes names and reports bad entries. `applyKeyOverrides` then checks every override against the actions of the same context (same group, or a global group: App, Move, Views) and skips the override with a message. `crm keys set` runs the same check (`ConflictFor`). | The check covers rebinds only. The built-in defaults are never checked, and "same context" is the action group, not the view and mode, so it misses real clashes (C1, C2, C3 are in different groups) and reports false ones. The generated audit is the first full check. Recommendation: make the audit a test with an allow-list of the known conflicts so a new conflict fails CI. |
| A list of chords per action | `[keys]` accepts one key or a list per action id (`favorite = ["f", "*"]`) and `crm keys set favorite f "*"` | Already there (herdr and Obsidian do the same). The first key is the one shown. |
| `?` lists active keys by context | `helpText` is generated from the registry, grouped by action group in a fixed order, with the effective keys. It lists every action, not only the ones active in the current view. | Partly. Recommendation: mark or hide actions whose `when` is false in the current context, and add a filter, as herdr's `prefix+?` and `/` do. |
| One footer rule | `footerSegs` lists enabled actions of the focused pane by `foot` priority, cut to the width. The bar footer lists the highlighted object's verbs. | Same rule in both. |
| Ctrl vs bare classes | not enforced | The Bare-keys and Ctrl-keys tables above are the violations. A test could check that no registry action with `write: true` has only a ctrl key, except the allow-list (ctrl+a, ctrl+z, ctrl+y). |
| Chords other layers swallow | `internal/keys` documents named keys; ctrl+i, ctrl+m, ctrl+h, ctrl+[ and ctrl+j are Tab, Enter, Backspace, Esc and newline in terminals | Not enforced when binding. Recommendation: `crm keys set` should warn on those and on shift or ctrl with symbols. |

## A4. Owner decisions (one per conflict, with a recommendation)

Nothing below is changed yet.

1. **C2 `e`.** Make `e` mean edit everywhere: take `e` off Mark contacted (keep `c`), so person edit, organization edit, deal edit and Company review rename agree. Recommend yes.
2. **C1 `s`.** Keep `s` for snooze (people, the main use). Move deal stage to `S` (shift is the heavier twin, as in herdr), keep Sync's run on `s` only inside the Sync view and Company review's skip on `s` as screen-local, and compare's survivor as modal. Recommend moving stage and sync run to a free letter or the palette: stage `S`, sync run `R`.
3. **C3 `p`.** Keep `p` for priority tier. Sync attach and Compare pair are screen-local, but Sync attach could become `A` and Compare pair `n` (next pair). Recommend leave unless the footer proves confusing.
4. **C4 `d` in Sync.** `D` is already dismiss in Merge, so there is no obvious letter. Recommend making Sync dry run a palette action with no key, so `d` means delete everywhere.
5. **C5 and C6 `m` and `r`.** Keep tag rename `r` and merge `m` on the tag row (lazygit precedent, doc). Move Merge's duplicate level off `m` to a palette action or `L`. Reload stays `r` outside the tag row. Recommend yes.
6. **Bare view navigation.** Keep vim motion (j k g G J K h l tab) and `/ : ? q`. Decide whether the digit keys and `[ ]` v stay bare. Recommend keep them, they are the tab bar the screen shows, and add `g` then letter later only if the owner wants Gmail style.
7. **`o` sort, `m` level, `T` type filter, `C` Company review.** Four view-level bare keys. Recommend moving them to palette-only actions with a ctrl key where one is wanted (`ctrl+o` sort), and keeping `C` as a convenience.
8. **Undo.** `ctrl+z` and `ctrl+y` stay. Optional: a bare `z` alias (Gmail, lazygit, Superhuman, doc and search) is free. Recommend yes, as an alias, because it works in the bar results focus without a chord.
9. **Test.** Turn the generated audit into a test that fails on a new conflict outside an allow-list, and extend `ConflictFor` to use the same probe. Recommend yes.
10. **`?` by context.** Mark inactive actions and add a filter to the help screen. Recommend yes.
11. **Terminal-swallowed chords.** Warn in `crm keys set` for ctrl+i, ctrl+m, ctrl+h, ctrl+[, ctrl+j and shift or ctrl with symbols. Recommend yes.
12. **ctrl+a.** Kept as the global add chord. If it collides with a tmux or screen prefix on the owner's machine, rebind it with `crm keys set add-any <key>`. No code change needed.
