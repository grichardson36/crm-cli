# Short syntax, pipe lines and autocomplete

Inline short syntax, live chips and hints, pipe-line prompts, the shared autocomplete and the related segment.

Moved from FEATURES.md on 2026-10-29. Every row keeps its ID and text. Update a row's State and Now in the same session you change the feature ([[keep-the-tracker-accurate]]). Column meanings and the row lifecycle are in [[feature-rules]].

**Follows patterns:** [[sigils-for-things-words-for-time]], [[at-sign-means-person]], [[hash-means-tag]], [[dates-are-plain-words]], [[by-means-deadline]], [[every-means-recurrence]], [[bang-means-priority]], [[duration-forms]], [[date-safety-rules]], [[show-parsed-chips]], [[show-syntax-inline-as-you-type]], [[autocomplete-component]], [[related-segment]], [[one-line-pipe-prompt]], [[unresolved-names-stay-text]], [[confirm-names-in-one-batch]], [[create-on-miss]]

**Research:** [[research-tui-building-blocks]]

**See also:** [[index]]

Inspiration: Super Productivity "short syntax" in the add-task bar (https://lanesawyer.github.io/super-productivity/wiki/how-to/2.03-add-tasks/): `#tag` assigns a tag (offer to create it), `@time` / `@date` sets due time/date (`@16:00`, `@tomorrow`, `@next week`, combine `@tomorrow @14:00`), `!date` / `!time` sets a deadline, `25m` or `t25m` sets an estimate and `t30m/` records time spent; each parsed value appears as a chip with a clear button; dialogs exist for the same properties; the syntax can be switched off. Goal for crm: the same idea for every text field that creates or edits a record, with one shared parser so the CLI, TUI, MCP and agents behave identically. Values are deterministic: the same text always yields the same fields.
