# Terminal UI: pipe-line prompts

Every pipe-line prompt (deal, task, note, organization, tag and the name of a new person) checks a segment through the one validation framework as soon as `|` closes it. An error shows inline in dim error style with its code, what was expected and the fix (`! E_DATE_INVALID due: ...`). The segment being typed shows only a soft indicator (`next friday -> Fri Oct 23`, `matches prospect, proposal`), never an error. Smart corrections (an email typed in a name) show as hints. `enter` still validates the whole line.

A popup opens under the segment being typed, fed by the field type: relation segments list objects (nicknames and typos match), choice segments their options (at most six rows), date segments natural phrases and dates tasks use, text segments nothing. While the popup is open `tab` accepts the highlighted row (after an object a `, ` is added for the next one, typing `|` takes it back), `up`/`down` move, `esc` closes the popup (a second `esc` cancels the prompt), `enter` submits the line. With no popup `tab` keeps its old job (the note type). Backspacing over a name takes that link out before it is saved. See crm help short-syntax for the grayscale syntax hint that still shows after the cursor.

Every add line (organization, deal, task, note, person, tag) ends with one segment, `related`, that takes objects of every kind the relation registry joins to the new object (people, organizations, deals, tasks, notes) and tags, separated by commas. Its suggestions come from where you are, in this order: the object you are on or have highlighted, that object's linked objects of every kind, once you chose something the objects linked to what you chose (one hop), then objects you used recently. Typing narrows by name (nicknames and typos match), a name that starts with `#` looks at tags only. What you already chose is never suggested again. The popup groups the rows by kind under dim headings (up to 12 rows, scrolling) and each row starts with a short kind prefix: `p:` person, `o:` organization, `d:` deal, `t:` task, `n:` note, `#` tag. The chosen objects show above the prompt as chips grouped in that order, each group in its kind color (theme roles `kind_person`, `kind_org`, `kind_deal`, `kind_task`, `kind_note`, `kind_tag`), wrapping onto more lines when needed. The prompt itself stays one line. A name that is no object yet offers pick-or-create with a choice per kind. A deal line keeps its organization and person fields, the people and organizations chosen in `related` link the same way (the first organization is primary).
